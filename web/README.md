# web

Web interface layer for this repository. Optional — add only when direct programmatic
access to the domain computer is insufficient for the intended use.

See [web conventions](../.yidam/.vendor/prelude/guidelines/directories.md) for what belongs
here.

This repository is one of the cases where a web layer is in scope from the outset: the goal
includes a public-facing platform for understanding Ohio school funding, and the audience
for that — school boards, journalists, legislative staff, parents — will not be running a
Rust CLI.

Three intended surfaces:

- **Agency view.** Pick a district or community school; see its funding history across
  regimes, in nominal and real dollars, with each figure linked to the formula component and
  parameter that produced it.
- **Regime view.** Walk the history — Foundation Program through the Fair School Funding
  Plan — with the bills, rulings, and parameter changes that moved it.
- **Scenario builder.** Perturb parameters, run the simulator, and see per-agency deltas on
  a map and a table. This is the surface the `scenario` class exists to serve.

The primary data source is a bundled export feed with a contract version, not the corpus
directly — the corpus is markdown and YAML meant for traversal, while the platform needs the
numeric series from `crates/`. Public-facing. Deployment target is undecided; static hosting
with a queryable data bundle is the presumption until the scenario builder's compute needs
are measured.
