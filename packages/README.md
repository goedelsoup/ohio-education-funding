# packages

Other-language packages in the same domain computer layer as [`crates/`](../crates/).
Use this directory when ecosystem access, ML frameworks, or upstream SDKs are better
served by Python, TypeScript, or another runtime than Rust.

The connector/calculator/feature-engineering distinction applies here equally — see
[packages conventions](../.yidam/.vendor/prelude/guidelines/directories.md).

Two capabilities in this domain belong here rather than in `crates/`:

- **Projection.** Carrying enrollment (ADM), assessed valuation, and revenue series forward
  is a statistical modeling problem, and the mature tooling is Python — `statsmodels` for
  the time-series work, `pandas`/`pyarrow` for the panel handling. The `foundation`
  simulator in `crates/` consumes projected inputs; it does not produce them.
- **Document extraction.** Much of the pre-2000 record exists only as scanned LSC and
  Department of Taxation publications. Table extraction from PDF is a Python ecosystem
  problem.

Rust remains the home for the formula simulator itself, where determinism and auditability
matter more than library breadth.

## Packages

| Package | Capability | Status |
|---|---|---|
| [`extract`](extract/) | connector / extraction | implemented, 26 tests, no dependencies |

[`extract`](extract/) is the retrieval half of the domain computer: it fetches the
department's publications, parses XLSX with the standard library alone, and writes the CSV
fixtures [`crates/`](../crates/) computes against. Run
`python3 -m ohio_edfund_extract --rebuild` and then the Rust gate — the fixtures are pinned by
tests, so a source revision that moves a finding fails there rather than passing silently.

Projection is still unimplemented; it is the other reason this directory exists.
